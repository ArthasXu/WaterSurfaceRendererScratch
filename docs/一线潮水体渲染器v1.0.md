# 从零手写一线潮水体渲染器 · 修订学习与实现方案

> 目标：在已有 Vulkan 渲染器基础上，逐步实现一个既能表现暴风雨大海浪，又能表现约 1 km 长距离“一线潮 / 潮涌前沿”的实时水体系统。  
> 核心策略：**FFT / Gerstner / 交互波 / 四叉树网格作为水体基础能力；一线潮作为叠加在基础水体上的大尺度可控 wavefront；泡沫、泥沙、碎浪主要由 shader 与特效完成。**

---

## 0. 总结结论

### 0.1 不应放弃 FFT

不做 FFT 也能用 Gerstner 波、sum-of-sines、噪声法线做出“有风吹起伏”的水面，但如果目标是**雷鸣闪电、恶劣天气、大尺度海面、远近尺度都自然的海浪**，FFT 仍然应该实现。

FFT 的价值不是做“一线潮”，而是做：

- 大尺度风浪统计分布；
- 多方向、多波长自然叠加；
- 风速、风向驱动的海面状态；
- 远处海面大面积起伏；
- 法线细节和海面粗糙感；
- 后续浮力、船体采样、海面状态查询。

### 0.2 一线潮不应完全交给 FFT

图中那种“一阵一阵、笔直、壮阔、白色前沿明显”的一线潮，更接近：

- shallow-water front；
- tidal bore；
- hydraulic jump；
- breaking wavefront；
- wave profile driven shoreline wave；
- shader foam front。

它不是常规 Tessendorf FFT 最擅长的对象。FFT 擅长“风浪背景”，不擅长稳定生成一条 1 km 长、近似笔直、可控推进、带碎浪白沫的潮头。

### 0.3 最优方案

最终水面高度场建议写成分层叠加：

```text
H_total(x, z, t)
= H_fft_ocean(x, z, t)              // 风浪背景
+ H_interactive(x, z, t)            // iWave / 波动方程交互扰动
+ H_bore_front(x, z, t)             // 一线潮主前沿
+ H_detail_normal(x, z, t)          // 小尺度法线/噪声细节
```

渲染层建议写成：

```text
WaterColor
= Fresnel反射
+ 水体透射 / 吸收 / 散射
+ 泡沫
+ 泥沙浑浊颜色
+ 暴风雨环境光照
+ 闪电瞬时高光
```

## 2. 为什么仍然需要 FFT

### 2.1 Gerstner 可以做风浪，但不够自然

Gerstner / sum-of-sines 可以做：

- 可控方向波；
- 风吹水面起伏；
- 中小规模波形；
- 低成本实时水面。

但它的问题是：

- 波的数量有限时容易看出重复；
- 恶劣海况下难以同时表现大浪、中浪、小浪的自然统计分布；
- 远处大面积海面缺少真实随机性；
- 参数靠手工调，难以从风速、风向自然生成海况。

### 2.2 FFT 是暴风雨海面基础层

Tessendorf / JONSWAP / Phillips 这类谱海面负责：

- 根据风速、风向生成波能量分布；
- 用 IFFT 得到空间域高度场；
- 生成 displacement map、slope map、normal map；
- 支撑大面积 ocean tile；
- 后续可以接 LOD / quadtree / clipmap。

所以，恶劣天气下的“大海浪起伏”建议由 FFT 主导。

### 2.3 一线潮是叠加层，不是替代 FFT

一线潮前沿不是普通背景海浪，而是一个额外的大尺度事件：

```text
H_total = H_fft + H_bore
```

这比“试图调 FFT 调出一条一线潮”更可控，也更性能友好。

## 3. 一线潮的推荐实现方式

### 3.1 一线潮的数学模型

定义水面水平坐标：

```text
p = (x, z)
```

定义潮头推进方向：

```text
d = normalize(direction)
```

定义某一点到潮头前沿的有符号距离：

```text
s = dot(p - origin, d) - speed * t
```

其中：

- `s = 0`：潮头前沿；
- `s > 0`：潮头前方，还未经过；
- `s < 0`：潮头后方，已经被潮水覆盖。

### 3.2 高度函数

第一版高度：

```text
H_bore(s)
= waterRise * (1 - smoothstep(-frontWidth, frontWidth, s))
+ crestAmp * exp(-(s / crestWidth)^2)
```

含义：

- `waterRise`：潮头后方整体水位抬升；
- `frontWidth`：潮头陡峭程度；
- `crestAmp`：前沿浪脊高度；
- `crestWidth`：前沿浪脊宽度。

### 3.3 后方扰动

潮头后方加入细节扰动：

```text
backMask = 1 - smoothstep(-trailLength, 0, s)

H_turbulence
= backMask * noise(p * noiseScale + flow * t) * turbulenceAmp
```

### 3.4 与 FFT 叠加

```text
H_total = H_fft + boreWeight * H_bore + H_turbulence
```

其中 `boreWeight` 可以用区域 mask 控制，让一线潮只在特定河口/江面区域出现。

### 3.5 泡沫 mask

泡沫不是单靠几何高度产生，而是用 mask 控制：

```text
Foam
= frontFoam
+ slopeFoam
+ trailFoam
+ noiseBreakup
```

推荐公式：

```text
frontFoam = exp(-(s / foamWidth)^2)

slopeFoam = smoothstep(slopeMin, slopeMax, |∇H_total|)

trailFoam = backMask * noise(p * foamScale + foamFlow * t)

Foam = saturate(frontFoam * 0.8 + slopeFoam * 0.5 + trailFoam * 0.4)
```

### 3.6 一线潮长度约 1 km 时的性能策略

不要生成 1 km × 1 km 全分辨率高密度网格。推荐：

- 网格用 quadtree / clipmap / concentric rings；
- 近处顶点密，远处顶点稀；
- 一线潮前沿附近强制提高 tessellation / LOD；
- 远处只用 normal map 和 foam impostor；
- 泡沫可用屏幕空间 / 贴图滚动，不一定用真实几何；
- FFT tile 可重复平铺，但 bore front mask 用世界坐标生成，避免一线潮重复感。

## 5. 阶段 5A：Tessendorf FFT 海面

### 目标

实现暴风雨大海面基础起伏。

### 必须理解

1. 海面是大量正弦波叠加；
2. 波谱决定每个波长/方向有多强；
3. 初始频域振幅由高斯随机数和波谱生成；
4. 色散关系决定每个波的相位如何随时间变化；
5. IFFT 把频域高度转回空间域；
6. slope / displacement / normal 都可以从频域导数得到。

### 实现步骤

```text
5A.1 写 WaveSpectrum 参数结构
5A.2 生成离散波矢量 k
5A.3 实现 Phillips 或 JONSWAP 谱
5A.4 生成 h0(k)
5A.5 实现 h(k, t)
5A.6 先写朴素 DFT 验证 N=32
5A.7 接 FFTW
5A.8 输出 height / displacement / normal PNG
5A.9 调高风速，验证大海浪效果
```

### 验收

- 能输出动态 height map；
- 风向变化后，波纹主方向改变；
- 风速变大后，大尺度起伏增强；
- 高度无 NaN、无爆点；
- 可以口述从 spectrum 到 height map 的全流程。

---

## 6. 阶段 5B：交互波 / 波动方程

### 目标

为后续船、障碍、雨滴、落水提供局部扰动能力。

### 实现方式

第一版使用离散波动方程：

```text
h_next = 2h_current - h_prev + c^2 Δt^2 ∇²h_current
```

加入阻尼：

```text
h_next *= damping
```

### 输入

- 鼠标点击扰动；
- 船体扰动；
- 雨滴随机扰动；
- 障碍物 mask。

### 输出

```text
InteractiveHeightMap
InteractiveNormalMap
```

### 验收

- 鼠标点击水面有圆形波纹；
- 波纹会传播和衰减；
- 可以与 FFT 高度相加；
- 不影响主海浪稳定性。

## 8. 阶段 6：四叉树 / LOD 水面网格

### 为什么需要

1 km 级水面如果使用等密度网格，顶点数会过高。四叉树或 clipmap 的作用是：

- 相机附近高精度；
- 远处低精度；
- 潮头附近提高精度；
- 减少 draw cost 和 vertex cost。

### 实现路线

第一版：

```text
固定多环 grid / clipmap
```

第二版：

```text
quadtree tile LOD
```

第三版：

```text
潮头前沿区域动态细分
```

### Tile 数据

每个 tile 记录：

```cpp
struct WaterTile {
    glm::vec2 worldMin;
    glm::vec2 worldMax;
    int lodLevel;
    bool intersectsBoreFront;
    bool visible;
};
```

### LOD 判断

```text
LOD = f(distanceToCamera, distanceToBoreFront, screenSpaceError)
```

### 验收

- 近处网格细，远处网格粗；
- 摄像机移动时无明显裂缝；
- 潮头附近精度足够；
- 1 km 水面仍保持稳定帧率。

## 9. 阶段 7：Vulkan 动态贴图上传 + 顶点位移

### Descriptor 设计

```text
binding 0: CameraUBO
binding 1: WaterParamsUBO
binding 2: FFTDisplacementMap
binding 3: FFTNormalMap
binding 4: InteractiveHeightMap
binding 5: BoreHeightMap / BoreParams
binding 6: FoamMap
binding 7: FlowMap
binding 8: Sky / Environment
```

### Vertex Shader

```text
worldXZ = tileWorldPosition + localGridPosition

fftDisp = sample FFTDisplacementMap
boreH   = computeBore(worldXZ, time) 或 sample BoreHeightMap
interH  = sample InteractiveHeightMap

worldPos.y += fftDisp.y + boreH + interH
worldPos.xz += fftDisp.xz
```

### Fragment Shader

```text
normal = combine(FFTNormal, boreNormal, detailNormal)
foam   = combine(BoreFoam, slopeFoam, trailFoam)
color  = waterOptics + foam
```

### 验收

- FFT 海面正常起伏；
- 一线潮前沿叠加在 FFT 上；
- 鼠标扰动或交互波可叠加；
- 泡沫与潮头位置对齐。

## 12. Fluid Flux 能否满足需求

### 能满足的部分

Fluid Flux 适合参考或直接用于 UE 验证：

- 浅水模拟；
- 河流 / 湖泊 / 海岸；
- advected foam；
- wave profiles；
- coastline wave break；
- ocean blending；
- dynamic interaction；
- Niagara 特效集成；
- underwater / caustics / waterline。

### 不完全满足的部分

对于你的自研 Vulkan 渲染器，Fluid Flux 不能直接满足：

- 它是 Unreal Engine 资产/插件，不是 Vulkan C++ 项目；
- 核心实现大量依赖 UE 渲染管线、材质系统、蓝图或插件框架；
- 你不能直接把它搬进自研 renderer；
- 真正 1 km 一线潮是否满足，需要看其 coastline / wave profile 是否能表达长直潮涌，而不只是岸线碎浪；
- 如果需要完全可控的物理一线潮，仍建议自己实现 WSBoreField / SWE。

### 最佳使用方式

```text
Fluid Flux = 视觉和架构参考 / UE 原型验证
自研 Vulkan = 学习与最终实现主线
```
