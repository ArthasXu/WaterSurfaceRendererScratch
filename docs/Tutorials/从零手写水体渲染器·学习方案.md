# 从零手写水体渲染器 · 完整学习方案

> 本方案目标：让一个**图形学初学者**，在不依赖 AI 改代码、不靠调参蒙混的前提下，
> 通过**自己一行行敲完**，最终独立写出本仓库 `WaterSurfaceRendering` 的全部代码，
> 并真正理解 **Vulkan 管线 → 物理波浪(FFT) → 网格 → Shader 渲染** 的完整原理。
>
> **铁律（请严格遵守，否则学不到东西）**
> 1. 每个阶段的代码**必须自己手敲**，不准复制本仓库源码，不准让 AI 代写。
> 2. 遇到不懂先查规范/书，再动手；卡住超过 2 小时可看仓库对应文件**找思路**，但看完要**关掉源码凭记忆重写**。
> 3. 每阶段都有"验收标准"，没达到不许进下一阶段。
> 4. 仓库源码只当"标准答案"用于**对照检查**，不当"抄写模板"。
> 5. 调参是最后才做的事；学习期一律用固定参数，先把"为什么这么写"搞懂。

## 阶段 5 ｜ ★Tessendorf 海洋谱 + FFT 物理（约 1.5~2 周）核心物理

**这一阶段完全脱离 Vulkan，在纯 C++ 控制台程序里做**，把结果输出成图片或文本验证。
对照 `src/scene/WSTessendorf.cpp/.h`，但**先读论文再写代码**。

### 5.1 必读理论（Tessendorf 1999《Simulating Ocean Water》）
理解这条主线：
1. 海面高度场是大量正弦波叠加 → 频域里就是一组复振幅 `h(k)`。
2. **Phillips 谱**：风驱动波的能量分布，决定每个波矢量 k 的初始振幅
   （对照 `WSTessendorf.h:249 PhillipsSpectrum`，搞懂公式里每一项：风速 L、风向 cos 因子、阻尼 damping）。
3. **初始频域振幅** `h0(k)`：高斯随机数 × √(Phillips)（`WSTessendorf.h:237 BaseWaveHeightFT`）。
4. **色散关系** `ω(k)=√(gk)`：决定波随时间如何相位演化
   （`DispersionDeepWaves`，以及为什么要量化 `QDispersion` 让动画循环）。
5. **时间演化** `h(k,t) = h0(k)e^{iωt} + h0*(-k)e^{-iωt}`（`WSTessendorf.h:265 WaveHeightFT`）—— 保证实数高度场。
6. **IFFT**：把频域 `h(k,t)` 逆变换回空间域 → 得到每个网格点的真实高度。
7. **choppy（横向位移）**：用 `ik/|k|` 加权得到水平位移，让浪尖更尖（Lambda 参数）。
8. **法线/斜率**：频域里乘 `ik` 得到导数，IFFT 后得到斜率，组装法线。

### 5.2 必须亲手实现（建议先用朴素 DFT 跑通，再换 FFTW 加速）
按 `WSTessendorf` 的方法名，自己实现：
- `ComputeWaveVectors()`：生成 `N×N` 的离散波矢量（`WSTessendorf.cpp:60`，搞懂 `2πn/L` 那条公式）。
- `ComputeGaussRandomArray()`：高斯随机数组。
- `ComputeBaseWaveHeightField()`：算 `h0`、`h0*`、色散 ω（`WSTessendorf.cpp:105`）。
- `ComputeWaves(t)`：每帧——
  1. 算当前频域高度场；
  2. 频域乘 `ik` 得斜率/位移/位移导数；
  3. **执行 IFFT**（这就是 FFT 所在！`WSTessendorf.cpp:284`，IFFT 调用在 `342-378`）；
  4. 处理符号翻转 `(-1)^(m+n)`（频谱中心化，`kSigns`）；
  5. 组装 `m_Displacements`(vec4: dispX, height, dispZ, jacobian) 和 `m_Normals`(vec4: slopeX, slopeZ, dDxdx, dDzdz)；
  6. `NormalizeHeights` 归一化高度到 [-1,1]。

### 5.3 FFT 具体怎么接
- 先**自己写一个朴素 2D DFT**（O(N⁴)，慢但能验证正确性），跑 N=32。
- 再换 **FFTW**：`fftwf_plan_dft_2d(..., FFTW_BACKWARD, FFTW_MEASURE)`
  （`SetupFFTW` `WSTessendorf.cpp:150`），`fftwf_execute` 执行（`ComputeWaves` 内）。
- 理解：plan 是"预先规划好的变换路径"，建一次反复执行；BACKWARD = 逆变换（频域→空间）。
- 可选：用 OpenMP `#pragma omp sections` 并行多个 FFT（`WSTessendorf.cpp:338`）。

### 5.4 验证手段（不靠眼睛，靠输出）
- 把某一帧的高度场写成灰度 PNG，看是否像水面（有连续起伏、无突刺）。
- 检查归一化后高度在 [-1,1]。
- 改风速/风向，看波纹方向是否合理（先理解，**别急着调参玩**）。

**阶段验收**：
- 控制台程序能稳定输出每帧的位移图/法线图数据。
- 能口述"从 Phillips 谱到屏幕高度"的完整数据流。
- 关掉源码，能独立写出 `ComputeWaves` 的主干逻辑。

> 常见坑：频谱中心化符号翻转漏了（水面会错位/抖动）、复数共轭对称没保证导致高度出现虚部、波矢量 k=0 没特判（除零）。

## 阶段 7 ｜ ★片元着色：Fresnel / 折射 / 水体光学（约 1.5 周）核心渲染

对照 `shaders/WaterSurfaceMesh.frag` + `WaterSurfaceUBO`（`WaterSurfaceMesh.h:260`）。
**先理解光学原理再写 shader**。

### 7.1 理论（Tessendorf [1] + Baboud&Décoret [3] + Premože&Ashikhmin [2]）
最终出射辐射度：
```
L = F_r·L_s + F_r·L_a + F_t·L_u
```
逐项搞懂：
- **F_r / F_t**：Fresnel 反射率/透射率，空气↔水 IOR=1.0/1.33477（`frag:40`）。自己推 Fresnel 公式或用 Schlick 近似。
- **L_s**：太阳直接反射进相机（Blinn-Phong 高光）。
- **L_a**：天空漫反射光（阶段 8 的 Preetham 提供）。
- **L_u**：水下上来、被折射进相机的光。

### 7.2 水下光线追踪（Baboud&Décoret 算法，自己实现）
对照 README "How it Works" 第 1-9 步：
1. 相机→片元构造视线 `r_v`。
2. 算 Fresnel 反射率。
3. 折射方向 `t`（Snell 定律），构造折射射线 `r_t`。
4. `r_t` 与水下深度 `d` 处的水平假想地面求交 `p_g`（`frag:46 kTerrainBoundPlane`）。
5. 采样地面颜色/法线（可用 value noise 做简单海底）。
6. 沿 `r_t` 路径做**吸收 + 散射**衰减得 `L_u`。

### 7.3 水体光学系数（理解，别死记）
- **吸收系数 / 散射系数 / 后向散射系数**：来自 Jerlov 水体分类（`WaterSurfaceMesh.h:293` 起的 `s_kWaterTypesCoeffs`）。
- RGB 三波长 (680/550/440nm) 分别衰减 → 这就是水为什么偏蓝绿。
- 实现 `ComputeScatteringCoefPA01 / ComputeBackscatteringCoefPA01`（`WaterSurfaceMesh.h:369`）。

### 7.4 写 frag shader
按上面把 `L` 各项组合，先实现"只有反射"，再加折射，再加水下衰减，**分步验证**每加一项画面合理。

**阶段验收**：水面有真实的"近处透绿、远处反天/反光、掠射角强反射(Fresnel)"效果。能逐项解释画面里每块颜色来自公式哪一项。

> 常见坑：Fresnel 用错入射角、折射射线与平面求交方向反了（采样到水面上方）、RGB 衰减只用单通道导致水不变蓝绿。

## 阶段 8 ｜ Preetham 天空模型 + 合成（约 4~6 天）

对照 `scene/SkyModel.cpp`、`scene/SkyPreetham.cpp`、`shaders/SkyPreetham.frag`、`shaders/FullScreenQuad.vert`。

### 8.1 Preetham 解析天空（[5] Preetham et al. 1999）
- 理解天空亮度是 **太阳方向、观察方向、浊度(turbidity)** 的解析函数。
- 实现 Perez 模型的 A~E 系数、天顶亮度 `ZenithLum`（`SkyPreetham.cpp` 计算，传进 `WaterSurfaceUBO.sky`）。
- 自己实现 `SkyModel` 类：算系数 → 填 UBO → 提供给水体 frag 当 `L_a`。

### 8.2 天空渲染（全屏）
- `FullScreenQuad.vert`：用一个覆盖全屏的三角形/四边形，无需顶点缓冲（gl_VertexIndex 生成）。
- `SkyPreetham.frag`：按视线方向算天空色。
- **绘制顺序**：先画天空（不写深度），再画水面，再画 GUI（`WaterSurface.cpp:183`）。理解为什么天空不写深度。

### 8.3 整合
- 水体 frag 的 `L_s`（太阳）、`L_a`（天空）现在都由 SkyModel 提供，画面统一。

**阶段验收**：能切换日出/正午/黄昏（改太阳方向），天空与水面光照一致联动。理解 `SkyLuminance` 如何同时服务天空和水面。

## 通用学习方法（每个阶段都这么做）

1. **读 → 想 → 写 → 验 → 复盘**：先读理论/规范，想清楚数据流，自己写，跑验收，再对照仓库复盘差异。
2. **每阶段写一份笔记**：用自己的话画数据流图 + 对象依赖图 + 踩坑记录。
3. **Validation Layer 当老师**：任何报错都先读懂再改，不要瞎试。
4. **小步验证**：复杂 shader/物理分步骤加，每加一步确认画面/数据合理。
5. **"关源码重写"训练**：看了仓库找思路后，必须关掉源码凭理解重写，否则等于抄。
6. **禁止过早调参**：参数含义没吃透前一律用默认值，把"为什么"搞懂优先于"好不好看"。
