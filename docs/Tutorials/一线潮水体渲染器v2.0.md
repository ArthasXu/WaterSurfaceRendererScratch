# 一线潮水体系统：实现计划评审与修订版

> 适用背景  
> 1. 当前自研 Vulkan 学习渲染器已经完成窗口、相机、顶点/索引缓冲、UBO、Descriptor、静态 2D Texture 等基础能力。  
> 2. 目标游戏项目已经存在 FFT 海面、波动方程交互水波和四叉树水面。  
> 3. 最终目标是在雷雨、强风等恶劣天气下，同时表现自然的大尺度风浪和约 1 km 长、连续推进、带白色破浪前沿的“一线潮”。  
> 4. 本文评审对象是此前生成的“Level 1 程序化潮头 → Level 2 一维 SWE → Level 3 二维 SWE/Boussinesq”实现计划。

---

## 1. 总体结论

原计划的**物理分层和验证思路基本正确**，但不适合原样执行。

综合评价：

| 维度 | 评价 |
|---|---|
| FFT 数学学习路线 | 合理，可作为独立学习支线 |
| Level 1 程序化潮头 | 合理，但最终形状不应只靠高斯函数 |
| Level 2 一维 SWE | 有研究价值，但不应阻塞第一版产品效果 |
| Level 3 二维 SWE/Boussinesq | 理论正确，但明显超出当前第一阶段范围 |
| Vulkan 接入顺序 | 大体合理，深度缓冲和固定网格应优先 |
| 对已有项目能力的利用 | 不足，重复规划了已有 FFT、交互波和四叉树 |
| 对 Fluid Flux 的借鉴 | 不完整，遗漏了最关键的 Wave Profile 动画贴图体系 |
| 泡沫系统 | 过于简化，只有生成 mask，没有完整动画与输运 |
| 1 km 性能设计 | 方向正确，但应优先复用已有四叉树，而不是重写第二套 LOD |

最终建议不是推翻原计划，而是将其改成两条并行路线：

```text
学习路线：
Gerstner → CPU FFT → 动态浮点纹理 → 水体 Shader
目标：理解算法并独立手写

产品路线：
接入已有 FFT / 波动方程 / 四叉树
→ Fluid Flux 式移动前沿场
→ 2D Wave Profile 动画贴图
→ 泡沫动画
→ 暴风雨光学
目标：尽快做出可落地的一线潮
```

两条路线共享数学、数据格式和 shader，但不能混成一条超长串行任务。

# 3. 原计划中合理、应该保留的部分

## 3.1 Level 1 → Level 2 → Level 3 的分级思想

这个分级是正确的：

```text
Level 1：视觉可控，不保证守恒
Level 2：一维横截面守恒，沿长前沿展开
Level 3：局部二维守恒模拟
```

这样可以防止一开始就掉进完整二维浅水方程、地形源项、干湿边界和 GPU 求解器的工程深坑。

## 3.2 先固定网格，再接 LOD

第一版先使用固定 Grid 验证：

- 顶点位移；
- 法线；
- 泡沫位置；
- 前沿连续性；
- FFT 与潮头混合；

之后才接四叉树，这是正确顺序。

但在目标项目里，固定 Grid 验证完成后应**接现有四叉树**，而不是自行再实现一套 Clipmap，然后再实现一套 Quadtree。

## 3.3 CPU 物理先单测，再接 Vulkan

以下结构应保留：

```text
纯 CPU 数据生成
→ 输出 PGM/PNG/CSV
→ 验证数学
→ 动态纹理上传
→ Vertex/Fragment Shader
```

这对 FFT 和 SWE 都非常重要。

## 3.4 Level 3 内不能继续简单叠加 FFT 与 SWE

原计划指出：

```text
局部 SWE 域内：
使用 SWE 完整水面状态

局部 SWE 域外：
使用 FFT

重叠带：
只为消除视觉接缝而混合
```

这是正确的。二维 SWE 的 `h` 已经是完整水深状态，不能在模拟域内部再直接加一个完整 FFT 高度场，并声称物理守恒。

## 3.5 一维 SWE 先用有限体积方法

用 Rusanov/HLL 通量、CFL 时间步和 positivity 保护做第一版，比中心差分更合理。

不过第一阶 Rusanov 数值耗散较大。正确性通过后，再升级：

```text
MUSCL 重构
+ minmod / MC limiter
+ SSP-RK2
```

不需要第一版就实现高阶格式。

# 4. 原计划最需要修改的部分

## 4.1 问题一：重复实现目标项目已经具有的系统

原计划依次安排：

```text
重新实现 CPU FFT
重新实现交互波
重新实现四叉树
然后实现一线潮
```

这对于“从零学习”合理，但对于当前产品目标不合理。

### 修改方式

建立统一数据源接口：

```cpp
struct WaterSurfaceSample
{
    float height;
    glm::vec2 horizontalDisplacement;
    glm::vec2 slope;
    glm::vec2 velocity;
    float foamSource;
    float blendMask;
};

class IWaterSurfaceSource
{
public:
    virtual ~IWaterSurfaceSource() = default;

    virtual void Update(float deltaTime) = 0;
    virtual WaterSurfaceSample Sample(glm::vec2 worldXZ) const = 0;
};
```

目标项目中实现适配器：

```text
ExistingFFTAdapter
ExistingInteractionWaveAdapter
ExistingQuadtreeAdapter
BoreFrontSource
```

自研学习项目中再实现：

```text
WSTessendorf
WSGerstner
WSWaveEquation
SimpleGridWater
```

这样不会把学习代码强行变成生产代码。

## 4.2 问题二：遗漏 Fluid Flux 最关键的 Wave Profile 动画贴图

原计划的潮头横截面主要使用：

```text
smoothstep 水位抬升
+ Gaussian crest
+ sin 后方波列
```

这些适合作为数学调试，但不足以复现 Fluid Flux 那种可控的翻卷浪头。

Fluid Flux 的关键不是单个高斯函数，而是：

```text
Front / Coastline Distance Field
+
2D Wave Profile Texture
+
World-space Direction
+
Foam Advection
```

### 必须新增：Bore Wave Profile

建议增加：

```cpp
class BoreWaveProfile
{
public:
    void LoadOrGenerate(...);

    // 横轴：到潮头的距离
    // 纵轴：动画相位
    glm::vec4 Sample(float normalizedDistance,
                     float animationPhase) const;
};
```

推荐通道：

```text
R = 沿潮头传播方向的水平位移
G = 垂直位移
B = 泡沫源强度
A = 流速、破碎权重或辅助位移
```

采样方式：

```glsl
float profileU =
    saturate(signedDistance / profileWidth * 0.5 + 0.5);

float profileV =
    fract(time * profileAnimationSpeed
        + alongFrontPhaseOffset);

vec4 profile =
    texture(boreWaveProfile, vec2(profileU, profileV));
```

### Wave Profile 的生成方式

学习版按 Fluid Flux 思路生成：

```text
多条 2D 曲线表示不同动画帧
→ 每条曲线描述浪头横截面
→ 烘焙为 2D 浮点纹理
```

第一版也可以手工生成一张简单 LUT，但最终不应只靠高斯函数。

## 4.3 问题三：需要把“潮头曲线”和“浪头剖面曲线”分开

原计划只有 `BoreFrontCurve`，但实际需要两种完全不同的曲线。

### A. 潮头空间曲线

决定 1 km 浪线在世界中的形状：

```text
alongFront → frontOffset
```

适合存成一维 LUT。

### B. 浪头横截面动画曲线

决定从潮头前方到后方的具体几何：

```text
distance × animationPhase
→ forward / upward / foam
```

适合存成二维 Wave Profile Texture。

两者不能合并：

```text
Front Curve：决定“浪线在哪里”
Wave Profile：决定“浪线长什么样”
```

## 4.4 问题四：弯曲前沿的导数计算不完整

原计划从直线潮头升级成：

```text
s = crossFront - speed * time - f(alongFront)
```

这是非常适合 1 km 轻微弯曲前沿的低成本表达。

但是法线不能继续只使用固定 `normal`。

设：

```text
n = 基础推进方向
t = 沿前沿切向
a = dot(p - origin, t)
s = dot(p - origin, n) - ct - f(a)
```

则：

```text
∇s = n - f'(a)t
```

因此潮头局部推进方向应为：

```cpp
glm::vec2 localFrontNormal =
    glm::normalize(normal
                 - curveDerivative * tangent);
```

潮头坡度为：

```text
∇H = dH/ds · ∇s
```

如果不加入 `f'(a)`，曲线弯曲后几何法线、泡沫方向和流速方向会与浪线不一致。

## 4.5 问题五：泡沫系统只有“生成”，缺少“动画”

原计划的：

```text
frontFoam
+ slopeFoam
+ trailFoam
```

只能得到泡沫 mask，容易像固定白色贴纸。

Fluid Flux 的泡沫层还会根据速度对纹理进行三相位平滑滚动，使纹理循环时不会明显跳变。

### 第一版：三相位动画泡沫

```text
相位 0
相位 1/3
相位 2/3
```

分别沿速度方向采样，再使用周期权重混合。

建议实现：

```glsl
FoamDetail SampleAdvectedFoam(
    vec2 worldXZ,
    vec2 velocity,
    float time);
```

### 第二版：状态型泡沫

后续再增加 Ping-Pong Foam Texture：

```text
上一帧泡沫
→ 按 velocity 回溯采样
→ 加 foamSource
→ 衰减
→ 少量扩散
```

更新形式：

```text
F_next(p)
=
F_prev(p - velocity·dt)
+ source·dt
- decay·F_prev·dt
```

### 分离两个概念

```text
Foam Source：哪里产生泡沫
Foam Appearance：泡沫表面纹理长什么样
```

原计划把两者混在了一起，应拆开。

## 4.6 问题六：缺少高频动画贴图层

即使几何使用 FFT，仍需要 Fluid Flux 式表面动画层：

```text
多尺度法线贴图
泡沫细节贴图
Flow Map
泥沙/浑浊噪声
细小破浪纹理
```

推荐增加：

```text
LargeNormalMap
SmallNormalMap
FoamNormalSoftHeightMap
NoiseMap
FlowMap
```

这些贴图不负责大尺度水面几何，而是负责：

- 打破 FFT 网格分辨率限制；
- 提升近景细节；
- 让浪后泡沫沿水流方向移动；
- 在闪电照明时提供丰富高光变化。

## 4.7 问题七：缺少 Gerstner 波的正式位置

Gerstner 不应替代 FFT，但应保留为：

```text
FFT 未接入前的快速几何测试
近景定向浪
艺术可控的 swell
Wave Profile 之外的附加浪脊
GPU Compute/Vertex Shader 学习模块
```

建议在学习路线中增加：

```text
Stage 5A0：4～8 条 Gerstner Waves
Stage 5A1：Tessendorf FFT
```

在生产路线中，如果已有 FFT，则 Gerstner 是可选项，不是阻塞项。

## 4.8 问题八：CPU 每帧上传 RGBA32F 成本偏高

原计划为 FFT displacement、normalAux、交互波和泡沫分别上传动态纹理。

作为学习版可以这样做，但生产版不应长期依赖：

```text
CPU FFT
→ 多张 RGBA32F
→ 每帧 staging
→ GPU
```

例如 512×512 的一张 RGBA32F 约为 4 MiB，两张约 8 MiB；每帧上传会增加 CPU、PCIe 和同步压力。

### 建议分级

#### 学习版

```text
N = 64 / 128
CPU FFT
RGBA32F
vkQueueWaitIdle 先保证正确
```

#### 优化版

```text
持续映射的 ring staging buffer
每帧独立资源
明确 pipeline barrier
RGBA16F
异步 transfer
```

#### 生产版

```text
FFT 和交互波留在 GPU
Compute Shader 直接写 Storage Image
Vertex Shader 直接采样
避免 CPU readback 和重复上传
```

## 4.9 问题九：纹理格式应按用途区分

建议：

| 数据 | 第一版格式 | 优化格式 |
|---|---|---|
| FFT displacement | RGBA32F | RGBA16F |
| FFT slope/normal aux | RGBA32F | RGBA16F |
| Bore Wave Profile | RGBA16F | RGBA16F |
| Front Offset LUT | R32F | R16F/R32F |
| Interaction Height | R32F | R16F |
| Flow Map | RG32F | RG16F |
| Foam Source | R16F | R8/R16F |
| SWE State | RGBA32F | 通常继续 RGBA32F |

SWE 的状态更新对稳定性更敏感，不建议一开始使用半精度。

## 4.10 问题十：Level 2/3 过早、范围过大

原计划从 FFT 一路写到 Boussinesq，实际会形成数月级工程。

对当前视觉目标：

```text
FFT
+ Fluid Flux 式 Wave Profile 潮头
+ 泡沫
+ 现有四叉树
```

已经可以得到高质量第一版。

因此：

```text
1D SWE = 物理升级支线
2D SWE = 可选研发项目
Boussinesq = 只有明确需要 undular bore 时才做
```

它们不应是第一版 Demo 的必经路径。

# 5. 修订后的最终系统架构

## 5.1 水面数据源

```text
Existing FFT Ocean
        │
        ├── displacement
        ├── slope
        ├── Jacobian / breaking hint
        └── velocity hint
                │
Existing Interaction Wave
        │
        ├── local height
        ├── local slope
        └── local mask
                │
Moving Bore Front
        │
        ├── signed distance
        ├── local direction
        ├── profile displacement
        ├── foam source
        └── flow velocity
                │
                ▼
        Water Surface Composer
                │
        ├── final displacement
        ├── final slope
        ├── final foam source
        ├── final velocity
        └── LOD importance
```

## 5.2 Level 1 的几何组合

```text
P_final
=
P_grid
+ D_fft · W_fft
+ D_interaction
+ D_bore
```

其中潮头中心应压低 FFT：

```text
W_fft = mix(1, crestFFTScale, crestMask)
```

推荐：

```text
crestFFTScale = 0.2 ～ 0.6
```

这样随机 FFT 波峰不会切断连续的一线潮轮廓。

## 5.3 法线组合

不要直接线性相加单位法线。

应合并坡度：

```text
slopeTotal
=
slopeFFT · weightFFT
+ slopeInteraction
+ slopeBore
+ slopeDetail
```

最后统一构造：

```glsl
vec3 normal =
    normalize(vec3(
        -slopeTotal.x,
         1.0,
        -slopeTotal.y
    ));
```

## 5.4 泡沫组合

```text
foamSource
=
max(
    profileFoam,
    slopeFoam,
    fftJacobianFoam,
    interactionFoam
)
```

然后使用动画细节纹理：

```text
foamAppearance
=
foamSource × advectedFoamTexture
```

最终泡沫同时修改：

```text
BaseColor
Roughness
Specular
Normal
Opacity
Emissive（闪电时可增强）
```

# 8. BoreFrontField 设计

## 8.1 低成本 1 km 表达

对于近似笔直、只有轻微弯曲的一线潮，不需要对任意 spline 做逐段最近点搜索。

定义：

```text
n = 基础推进方向
t = 前沿切向
a = dot(p - origin, t)
ξ = dot(p - origin, n)
```

潮头位置：

```text
ξ_front(a,t)
=
speed · time
+ offsetCurve(a)
```

有符号距离：

```text
s = ξ - ξ_front(a,t)
```

复杂度：

```text
2 次 dot
1 次一维 LUT
若干标量计算
```

适合在每个水面顶点执行。

## 8.2 局部方向

```text
∇s = n - offsetCurve'(a)t
```

局部潮头法向：

```text
frontNormal = normalize(∇s)
```

## 8.3 沿潮头变化参数

建议准备多张一维 LUT，或一张 RGBA LUT：

```text
R = front offset
G = crest amplitude multiplier
B = foam multiplier
A = phase offset
```

这样 1 km 浪线不会完全同步、完全同高。

# 9. Bore Wave Profile 设计

## 9.1 UV 定义

```text
U：到潮头的有符号距离
V：浪头动画相位
```

## 9.2 通道定义

```text
R：forward displacement
G：upward displacement
B：foam source
A：velocity / breaking / auxiliary
```

## 9.3 额外水位抬升

Wave Profile 负责翻卷浪形；潮后水位需要单独加入：

```text
backMask =
1 - smoothstep(-riseWidth, riseWidth, s)

waterRise =
riseHeight · backMask
```

最终潮头位移：

```text
D_bore
=
frontDirection · profile.forward
+
up · (profile.upward + waterRise)
```

## 9.4 后方次级波列

第一版可以使用 profile 自带的后方波列。

也可以额外叠加：

```text
trailEnvelope · sin(k·s - ωt)
```

但不要让其振幅超过主潮头，避免破坏阅读层级。

# 15. 对原计划的最终判定

原计划不是错误，而是存在三个主要问题：

1. **把学习路线和产品路线混在一起。**
2. **没有真正落实 Fluid Flux 最核心的 Wave Profile + Front Field + Foam Advection。**
3. **过早把 1D SWE、2D SWE 和 Boussinesq 全部列为串行必做项。**

修改后，最佳方案为：

```text
已有 FFT
+ 已有交互波
+ 已有四叉树
+ 移动 BoreFrontField
+ Fluid Flux 式 2D Wave Profile
+ 泡沫动画
+ 暴风雨水体渲染
```

浅水方程不是删除，而是降为后续物理升级：

```text
视觉版本先完成
→ 1D SWE 替换横截面
→ 必要时局部 2D SWE
→ 明确需要色散波列时再做 Boussinesq
```

这条路线同时满足：

- 当前 Vulkan 学习阶段不会跨度失控；
- 可以利用目标项目已经存在的系统；
- Fluid Flux 的有效实现思想被真正吸收；
- 一线潮长度达到 1 km 时仍然性能友好；
- 后续可以逐级升级到更可信的物理模型。
